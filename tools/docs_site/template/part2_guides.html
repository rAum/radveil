Arrays & DICOM#

Nothing requires a file. Build a volume from any float32 array and its voxel→RAS+ affine: a DICOM series read with pydicom or SimpleITK, an imaging application’s volume, or raw data. The volume is modified in place. For uploads and object stores, Volume.from_bytes(data) parses .nii/.nii.gz content and vol.to_bytes() encodes the result, with no temporary file.

[[tabs py="py/memory.py" rs="note:Volume::from_array(data: Array3<f32>, affine: Mat4) (a row-major 4×4 f64 array), then the same deface_auto call; the result is in vol.data." c="note:radveil_volume_from_array(nx, ny, nz, data, affine) copies your float buffer (C order) and a row-major 4×4 affine; read the result back from your own pipeline or save it with radveil_volume_save." sh="note:The CLI works on NIfTI files; convert DICOM first (for example with dcm2niix)."]]

Region only: process it yourself#

An API-only escape hatch. anonymization_mask runs detection, validation, the safety refusals and (optionally) the brain check, then returns the exact region deface_auto would rewrite. The volume is not touched. Escalations in deface_auto reuse the same region, so this is the final mask.

[[tabs py="py/region.py" rs="rs/src/bin/region.rs" c="c/region.cpp" sh="sh/region.sh"]]
Nothing is verified in this mode The mask says where RadVeil would anonymize, not that your processing of it hides the face. Check the result: render it and run detect_landmarks on the views, or run deface_auto on your output and expect a refusal.

Brain check & brain extraction#

Two opt-in safety options, sharing one brain extraction from the input (SynthStrip, pure Rust, ~3 s): brain_guard never modifies the brain or anything within 3 mm of it, and brain_check reports how many brain voxels were modified and how close the change came. Brain extraction is also available on its own.

[[tabs py="py/brain.py" rs="rs/src/bin/brain.rs" c="note:Pass RADVEIL_BRAIN_GUARD | RADVEIL_BRAIN_CHECK as brain to radveil_deface_auto (see the quick start) and read report.brain_voxels_modified; extract the brain with radveil_deskull." sh="sh/brain.sh"]]

Your own face detector#

The built-in detector (MediaPipe BlazeFace + Face Mesh, embedded) needs no setup. To use another model, give the pipeline 68 landmarks in the standard 68-point (iBUG) order on each rendered view; validation and verification still run. In C, hosts supply 68 world-space points directly.

[[tabs py="py/detector.py" rs="rs/src/bin/detector.rs" c="c/landmarks.c" sh="note:Pass 68 world-space points as JSON: radveil deface in.nii.gz out.nii.gz --landmarks3d points.json (see step by step)."]]

Whatever detector found the face, verification also attacks the output with the built-in one. In Python, detector="dlib" selects the optional dlib detector (pip install "radveil[dlib]" and fetch_predictor()): dlib's CC0 5-point model by default, eyes and nose base measured, mouth inferred, jaw unused. fallback_detector="dlib" instead keeps the built-in detector and processes only the scans it rejects, with the brain guard on (fallback_brain_guard=True); the report's fallback_used says which ran. dlib's research-only 68-point models are used only when passed as predictor_path, with a license warning.

Cohorts#

deface_batch runs workers volumes at a time (default min(cpu_count, 32, n)) on threads in one process: the Rust core releases the GIL, so threads scale like processes and share one copy of the detector models. executor="processes" isolates each volume in a spawned worker instead (then call it under if __name__ == "__main__":). Refused or failed inputs are reported, not raised.

[[tabs py="py/batch.py" rs="note:Call deface_auto per file from your own thread pool; each thread needs its own MediaPipeDetector." c="note:Call radveil_deface_auto per volume; errors are thread-local (radveil_last_error)." sh="sh/batch.sh"]]
